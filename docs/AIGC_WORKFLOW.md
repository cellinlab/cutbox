# 从影视素材证据到 AIGC 镜头制作

设计与调研日期：2026-10-17。本文描述 CutBox 的工作流、交接数据和验收要求；**不是已实现功能清单，也不是外部平台兼容性认证**。当前实现与实际测试范围见 [验证记录](VALIDATION.md)，生产流程依据见 [影视制作调研](research/PRODUCTION_PIPELINE.md)。

## 核心任务

CutBox 应让用户能完成：挑选可追溯证据 → 整理人物／场景设定集 → 拆出镜头需求 → 生成适用参考和交接说明 → 在选定平台制作 → 导回候选 → 比较、审阅、选用 → 归档或导出任务数据集。

“参考足够多”不等于“生成要求清楚”。每份参考要说明它约束的是人物身份、服装、环境、动作、镜头、声音还是风格；每个镜头还要写清楚可以改变与必须保持的部分。

## 外部平台：已核实什么、尚不能核实什么

用户所写的 **SeeDance** 暂按“可能指 ByteDance Seedance”理解，保留原始名称，不把拼写推断当作产品身份确认。LibTV 的确切产品与入口也尚未确认。

| 对象 | 本轮可核实的事实 | 尚未核实 | CutBox 的可靠交接方式 |
| --- | --- | --- | --- |
| Seedance／用户所写 SeeDance | 官方 Volcengine Python SDK 提供 Ark 内容生成任务类型；输入联合类型包含文本、图像 URL、音频 URL、视频 URL及 draft task；媒体输入有 `role` 字段 [A1–A3] | 未读到当前 Seedance 官方模型文档；不能据通用 SDK 断言每个模型都支持所有输入、角色枚举、时长／数量／分辨率上限，也未运行云端生成 | 导出参考文件、用途清单和提示词；人工选择实际模型。只有取得该模型的明确能力约束后，适配器才做针对性检查 |
| TapNow | 候选公开入口 `www.tapnow.ai` 的请求被本环境网络策略阻断 | 本轮未观察到真实界面、画布节点、模型集合、导入格式、API、工作区或项目共享行为 | 保持平台中立的镜头 brief 和本地素材交接；可记录人工使用的平台名称与输出来源，不伪造“已接入” |
| LibTV | 名称来自用户；对 Liblib／LibTV 候选入口的请求被本环境网络策略阻断 | 尚不能确认名称对应的官方入口及具体工作流；未核实项目、角色一致性、分镜、模型编排或导出能力 | 作为用户自定义平台记录；不猜测 API、价格、文件格式或平台专属参数 |

**SDK 已核实范围更具体地说：**任务类型中出现 `id`、`model`、`status`、`error`、`usage`、`seed`、`revised_prompt`、`generate_audio`、`duration`、`ratio`、`resolution` 等字段；状态注释包含排队、运行、成功、失败和取消。[A2] `role` 在输入类型中是字符串，本轮没有核实其服务端合法枚举。[A3] 这些是**代码所声明的通用数据面**，不证明特定账户、地区、模型版本或接口调用实际可用。

因而，不能把“首尾帧、人物一致性、多镜头、音画同步、深度控制、姿态控制”等目标自动写成上述任一平台已验证的能力。它们应分别成为可配置能力和待验证项；不支持专用控制输入的平台仍可接收普通参考图／说明，结果需要人工判断。

## 工作对象和信息流

| 对象 | 必需信息 | 与其他对象的关系 |
| --- | --- | --- |
| 原片证据 Evidence | 媒体 ID／摘要、时间范围、空间区域、标注类型、观察／解释／创作、审核状态 | 回到原片；成为某条设定的依据，不直接等于设定 |
| 资产设定集 Asset bible | 稳定身份、形态／服装／声音变体、必须保持的特征、允许变化的特征、正反例与未知项 | 一个实体可有多份版本和不同场次上下文；每条关键描述可追溯到证据 |
| 镜头需求 Shot brief | 叙事目的、主体与关系、起止状态、动作、构图／运镜、环境／灯光、时长／画幅、对白／声音、衔接要求 | 对应故事／镜头位置，并引用明确的资产与参考版本 |
| 参考项 Reference | 内部用途、顺序、来源、裁剪／变换、输出文件摘要、技术规格 | 同一文件可服务多种用途；平台转换单独记录，原文件保留 |
| 制作尝试 Generation take | 对应镜头、实际输入快照、平台／模型、任务标识、参数、结果、失败或中断原因 | 同一镜头有多次尝试；一份媒体可以成为候选或选用结果 |
| 审阅 QC | 检查项、结论、证据区间、缺陷说明、修改意见、审阅时间 | 对某个具体结果版本生效，不能随新版本自动继承 |
| 交付／数据集包 | 选用内容、任务说明、来源与变换链、标注、分组／划分、使用说明 | 交付只包含明确选择的版本；原片、生成内容与自动建议能区分 |

推荐的参考用途是 CutBox 内部语义，例如 `identity`、`appearance`、`environment`、`motion`、`camera`、`style`、`audio`。**这些不是任何外部平台已经确认的 API 参数。**适配器负责把内部语义映射到已核实的平台参数，无法表达的约束要在交接报告中保留。

## 一次实际创作如何操作

1. **定义作品目标。** 建立创作项目，填写用途、叙事意图、画幅、计划镜头与交付要求。使用者可以从原片观察出发，也可以完全原创。
2. **整理设定集。** 为每个人物、场景、道具和声音选择少量有代表性的证据。标出遮挡、视角差异、服装变化、台词含义和仍未知的信息；不要用相似度候选自动确认身份。
3. **逐镜头写 brief。** 用具体状态和动作描述镜头：“人物从桌边转身，右手始终持杯，视线移向门口”，比一串泛化风格词更容易验收。把剧情顺序与源视频秒数分别保存。
4. **准备参考。** 按镜头用途导出图片、片段、音频、裁剪、深度／姿态／蒙版。记录处理方法和时空变化；深度值不自动代表真实米数，单帧推理的闪烁不能被隐藏。
5. **审阅交接清单。** 查看准备好的镜头文本、引用文件、所用版本和待确认约束。导出文字／JSON／文件集合；不假设把 `.cbox` 上传到第三方就能被识别。
6. **在实际制作工具中执行。** 人工选择平台与模型，并按其当时界面／文档提交。若平台会改写提示词，应同时保留实际提交文本和平台返回文本。没有 API 集成时，不显示伪造的云端排队或生成成功状态。
7. **导回结果。** 对每个候选导入真实媒体，记录对应镜头与制作信息；任务成功但没有可解码结果时，不能当作已完成镜头。失败尝试也可记录原因，避免重复试错。
8. **比较并返工。** 按人物、动作、镜头、声音和连续性检查，对问题帧标注。选用某个结果时保留其他候选及拒绝理由；新需求产生新输入快照。
9. **交付与复用。** 把选用结果交给剪辑；将已审核且用途适合的材料编入参考集合或特定任务数据集，并保存来源、版本和使用说明。

## 0.3 take 记录与完整版本链的边界

本轮数据契约采用每镜头 `takes[]`，每条候选绑定一个已导入媒体；`outputMediaId` 单独表示当前选用输出。这样可以保存多次制作尝试，而不把新候选覆盖在同一条记录上。字段含义如下；这是 CutBox 的本地记录，不是对平台 API 的承诺。

| 字段 | 含义与未知值处理 |
| --- | --- |
| id／mediaId | 候选记录身份与其实际结果媒体；跨项目导入时一起重映射 |
| provider | 实际使用的平台／工具名称，人工填写；不暗示官方集成或账号已连接 |
| model | 实际模型标识或用户能够确认的显示名称；不知道就留空 |
| prompt | 用户记录的实际提交文本快照，不能随镜头当前文本变化而改写 |
| negativePrompt | 仅在实际使用时填写；避免把“应避免的内容”误报成平台参数 |
| seed | 用字符串保存实际已知的原值，保留大整数精度；未知留空，不能用 0 代替未知 |
| externalTaskId | 实际外部任务标识；人工操作无法取得时留空 |
| createdAt | **本地候选记录建立时间**，不表示平台生成时间 |
| notes | 人工修改、限制、参考映射、实际已知生成时间等补充说明 |

新候选需要自己的记录；关联新输出不能偷偷复用旧任务信息。已有 takes 不应因修改镜头当前需求而变成使用了新提示词。平台改写提示词可先保留在备注，但独立 `revisedPrompt`、参数原始回执、输入参考文件清单快照、完整 QC 版本史和版本过期提示，仍应作为后续数据深化项，不宣称已由上述字段全部实现。

## 《瑞克和莫蒂》题材的具体工作流示例

目标示例：制作一段 **15 秒、3 镜头的自写平行剧情练习**。下述故事“装置把两人带入纸片维度”是本例创作，不声称来自某一集，也不复述原片台词。15 秒及 4／5／6 秒拆分是本项目的创作目标，**不是平台能力上限**。

本仓库不下载、不内置商业剧集、角色截图、对白或演员声音。实际使用时，用户可导入自己已有、适合相应用途的材料；开发验收使用自制色块、原创示意图和自行录制的声音。

| 镜头 | 镜头需求 | 要准备与核对的材料 | 回收结果后检查 |
| --- | --- | --- | --- |
| 01 · 4 秒 | Rick 在工作台边发现装置读数异常；先看仪器，再看同伴 | 人物正侧面与服装证据、工作台空间、手持道具、视线／转身动作；为新增装置写原创说明 | 人物特征和服装是否稳定；手与道具接触是否合理；桌面空间与下一镜匹配 |
| 02 · 5 秒 | Morty 察觉墙面变成纸片，后退半步；一句自写反应台词 | 角色表情／站姿、两人相对高度、环境变化的原创分镜、独立录音或用户指定声音材料 | 反应节奏、脚部与地面、视线对接、说话者归属、台词与口型／音轨关系 |
| 03 · 6 秒 | 两人侧身穿过纸片裂口，装置留在画面前景 | 起止姿态、双人遮挡、裂口位置、运镜路径、前后景和声音衔接；必要时使用自制姿态／构图参考 | 身份是否交换、肢体与道具是否漂移、动作是否接续、环境变换是否前后一致 |

操作上，先把“角色是谁”与“该镜头中穿什么、知道什么、做什么”分开。原片观察可支持外观描述；新剧情中的情绪、动机、对白和后果标为创作。若参考里没有某个背面、口型或动作，保留未知，不让自动描述补成所谓原作事实。

声音同样单独管理：台词文本、表演要求、录音／合成结果、对应人物和时间锚点分别保存。此例可用自己录制的不同声线验证流程，并不需要复制演员声音。

## 使用范围与来源记录

素材可用于本地研究，并不自动说明它也适合云端上传、公开发布、商业使用、模型训练或声音克隆。CutBox 应让用户分别记录已有依据，未知项保持未知；元数据填写本身不产生授权，也不替用户作笼统法律结论。

有实际帮助的字段包括：来源作品／集数／地址、取得方式、作者或权利方、使用依据与证明位置、允许用途、限制、署名要求、有效期，以及平台／模型条款的记录日期。导出时按用途带出这些说明；本地整理不因未填写信息就被无理由禁止。团队如需更严格规则，应显式配置自己的导出政策。

## QC 与数据集复用

| 检查层 | 具体检查 | 结果如何使用 |
| --- | --- | --- |
| 技术 | 文件可解码、时长、尺寸／画幅、实际帧率、音轨、明显黑帧／截断 | 自动检查可以报告已测量事实；未测量项不能显示通过 |
| 身份与形态 | 人物／服装／道具一致性、手部接触、遮挡后重现、身份交换 | 由证据和人工审阅判定；相似度只是候选信号 |
| 行为与连续性 | 起止状态、动作次序、空间方向、视线、跨镜头持有物／状态 | 发现问题后定位具体区间和修改要求 |
| 叙事与声音 | 镜头是否完成叙事目的、台词／说话者／情绪、声音过渡 | 创作判断与技术检查分别记录 |
| 来源与用途 | 输入输出链、平台／模型信息、已确认用途与未确认项 | 给下游提供具体说明；不能从“生成成功”推导其他用途都已获准 |

数据集应按明确任务导出，例如服装检索、动作分类、时段定位、声音事件或镜头语言。源片、人工标注、模型建议、生成候选和人工确认结果必须可区分；不能把被审核为“创意可用”的成片自动视为训练真值。划分训练／验证／测试集合时，应考虑同一原片、相邻帧、同源裁剪与派生候选的分组，避免高度相关样本跨集合造成评估泄漏。

## 本轮确定的能力缺口

1. 平台身份与最新能力资料：SeeDance／Seedance 名称需保持可纠正；LibTV 官方入口尚未确认；TapNow 的实际工作流未观察。
2. 实际平台集成：本轮文档调研没有执行登录、上传、付费生成或 API 请求，不能报告这些平台已连通。
3. 参考条件兼容：内部参考用途、深度／姿态输出不代表平台原生接受相同条件；需要逐平台、逐模型验证。
4. 多候选与版本：本轮 `takes[]` 保存绑定媒体的候选与人工生成记录；完整输入参考快照、QC 历史、版本依赖与 stale 提示仍需继续深化。
5. 客观评估：端到端一致性、真实人物／复杂遮挡、音画同步和长篇跨镜连续性需要专门样本，不能靠一段演示视频概括。
6. 工业交付：OTIO、OpenAssetIO、USD、OCIO 或 IMF 的完整互操作均需独立实现与验收；`.cbox` 保持自身边界。
