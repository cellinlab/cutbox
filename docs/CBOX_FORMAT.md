# CBox 桌面清单 0.3 与原型格式

`.cbox` 是加密的描述与标注清单，旁边的 `media/` 保存对应素材。它不是视频编码格式，不是模型权重，也不是版权/授权证明。此实验不兼容任何现有同扩展名产品，发布稳定格式前需检查命名和格式冲突。

## 两个必须分开的决定

- **描述加密模式（本轮实现）**：`.cbox` 内 JSON 加密；外部素材仍是明文，可以独立播放。清单包含相对路径、字节数、SHA-256、标注，密文认证成功后再校验素材。
- **全包保密模式（后续）**：描述和媒体都加密，分块流式读取；需要明确分块认证、顺序、长度、截断防护、随机读取、密钥分发与恢复。不能把明文媒体文件夹压缩一下就称加密包。

不存在既让任意工具无需密钥直接读取素材、又保证这些素材保密的方案。用户选择加密描述并不自动意味着需要 DRM。

## 实验字节格式

| 区间 | 长度 | 内容 |
| --- | --- | --- |
| 0–7 | 8 | `CBOX 00 01 00 00`，确切字节以实现 MAGIC 为准 |
| 8–23 | 16 | 安全随机 salt |
| 24–35 | 12 | 安全随机 AES-GCM nonce |
| 36–末尾 | 可变 | UTF-8 JSON 的 AES-256-GCM 密文 + 16字节 tag |

KDF 为 scrypt(N=32768,r=8,p=1,length=32)，口令 UTF-8 编码、不做隐式规范化，至少12字符；长度限制不是高强度口令保证。header 全部作为 AAD 认证。每次封装重新随机生成 salt 和 nonce；重复 JSON 会产生不同密文。版本固定 KDF 参数，读取方不执行包自带的任意高成本参数。最大明文8MiB，最多1万素材/10万条标注；正式大库应分卷，不把所有帧 mask 内嵌到 JSON。

仅泄露版本、salt、nonce和密文长度；不在明文 header 放标题或人物信息。无压缩阶段，没有 zip 解包。临时输出0600、完成后不覆盖式原子发布，拒绝已有输出。

## Python 原型 JSON 子集

```json
{
  "schema": "cutbox.prototype/0.1",
  "collection_id": "synthetic-tone-example",
  "assets": [
    {"id": "tone", "path": "tone.wav", "size": 32044, "sha256": "由实际文件计算的64位十六进制摘要"}
  ],
  "annotations": [
    {
      "id": "a1", "asset_id": "tone", "predicate": "sound.description",
      "value": "Synthetic tone, not speech", "review_state": "accepted",
      "selector": {"type": "audio_samples", "start": 0, "end": 16000, "sample_rate": 16000}
    }
  ]
}
```

这是形状示意，摘要占位文字不可通过验证。运行 `scripts/cbox.py demo` 可生成真实 WAV、摘要和可验证 JSON。实验仅支持 asset 和 audio_samples；后者读取 WAV 头验证范围和采样率。未实现完整视频/空间/关系 schema，未审计任意扩展字段，不把通过原型检查解释为全本体合法。

## 导出与回读

Python 原型的 pack 读取已有清单与素材，验证后只写 `.cbox`，不复制、裁剪或打包媒体。传递时需要同时复制素材目录。verify 先认证解密，再验证 schema、ID引用、相对路径、大小、SHA-256和已支持的锚点；成功后只报告计数，不把敏感 JSON 打到终端。

路径只接受相对 POSIX 路径，拒绝 `..`、反斜线、驱动器/冒号、空路径段与符号链接；禁止同路径大小写冲突。包不含可执行命令，导入时不执行链接、脚本或自动网络下载。原型不防御另一个本机进程在校验期间并发替换文件的竞态；正式导出需使用受控 staging、文件句柄与快照验证。

SHA-256绑定内容，不证明作者身份。AEAD证明持有该密钥的数据一致性，不证明密钥持有人是谁。后续有跨组织来源签名需求时另加签名身份和撤销机制；不要从加密推导可信作者。

## 稳定格式前的缺口

完整本体与稳定迁移规范、跨实现兼容测试向量、增量大集合、全包流式加密、密钥轮换/系统钥匙串、多接收者密钥封装、视频与多轨时间映射、安全评审尚未实现。桌面 0.3 已兼容读取桌面旧版本，具体边界见下文。丢失口令不能恢复；实验数据保留明文源与备份。正式版本优先评估成熟容器/加密封装能否承担外层，不自行发明密码算法。

## Electron 桌面包（已实现）

`desktop/packages.mjs` 使用相同的字节信封与固定密码学参数，导出的明文 schema 为 **`cutbox.desktop/0.3`**，可读取桌面 `0.1`、`0.2`、`0.3`，旧包缺失的新数组视为空。它与 Python 的 `cutbox.prototype/0.1` 是两种不同清单，当前没有自动迁移或互相导入支持；不能因信封相同就认为应用层兼容。

桌面清单保存 `media`、`entities`、`annotations`、`collections`、`templates`、`events`、`relations`、`stories`、`productions` 九个数组。媒体记录包含相对 `media/<sha256>.<扩展名>` 路径、字节数和 SHA-256；实体包含类型、名称、说明、标签、关联媒体和封面；标注保存源媒体、可选实体、秒级区间、说明、审核状态及空间几何；集合保存这些对象的 ID 引用。制作项目包含镜头计划、实体／证据引用、提示词、连续性、当前选用输出与绑定实际媒体的 `takes[]`。源文件绝对路径和本机缩略图路径不写入导出清单。实体选择和集合选择会携带所需依赖，导出的集合引用必须完整。字段定义见[数据模型](DATA_MODEL.md)。

导出在同级临时目录中复制媒体，核对复制结果与库内记录的大小和 SHA-256，源文件被原地修改时拒绝导出，避免把旧标注悄悄绑定到新内容。清单加密完成后，独占保留新的目标目录再以重命名发布内容；已有目录（包括空目录）不会被覆盖。发布前可能短暂看到空的保留目录，失败时清理自己创建的临时文件。

**默认 `full` 桌面集合包复制完整源媒体，不会按标注区间裁剪。** 包含一个片段的标注，也会携带它引用的整部源视频；素材体积和共享范围应据此判断。独立参考视频/片段导出是另一条媒体处理流程，不能把集合导出称为已裁剪片段包。外部 `media/` 始终是明文。

导入先验证信封认证、8 MiB 清单上限、计数、ID 引用、区间、相对路径、文件大小与摘要，拒绝路径穿越与符号链接；再复制到新的本地托管目录，并重新校验副本。领域服务通过 SQLite 事务导入快照、重新分配对象 ID、按内容摘要去重媒体并重映射引用；事务失败不写入部分元数据。文件复制与 SQLite 不属于同一个原子事务，调用方负责数据库导入失败时清理新建的托管目录。

上述检查不构成对恶意本机并发进程的隔离，也不证明素材作者身份。完整本体、稳定迁移协议、跨实现兼容向量及独立安全审计仍待完成。

## 0.3 图结构与选择导出

完整库导出保留模板、事件、关系、故事、制作项目、属性、角色／演员关联、标注的认识状态／可空置信度、模板值、多边形、关键帧、逐词与关键点。take 的模型、实际提交提示词快照、可选字符串 seed、外部任务 ID 和本地记录时间随制作项目保存；当前选用输出与其他候选分别引用素材。

选择导出包含所选实体及演员依赖、关联媒体／标注、被标注使用的模板；只有全部实体与证据已在选择内的事件／关系才携带。故事只有引用的全部媒体和事件已包含且至少引用一项选中素材／事件时才携带。制作项目同样要求项目及所有镜头引用的实体、标注、选用媒体、take 媒体全部已在选择中，且至少存在一项选择关联；不会为了携带项目而自动扩大到其他作品。不能闭合的事件／关系／故事／制作项目整体排除。完整库导出保留不依赖素材的草稿。

导入重建九类对象及镜头／take ID，并重映射媒体、实体、标注、事件和模板引用；外部任务 ID 与外部来源锚点不变。未知置信度保持 `null`，不把故事或提示词中的创作内容提升为观察事实。

## trimmed 媒体配置

`trimmed` 对满足条件的非图片素材使用所选标注和故事片段的最小起点到最大终点作为一个连续范围，FFmpeg 解码并重新编码；不会把不连续片段拼接或逐标注拆文件。没有标注、只有零长标注，或故事节点未指定范围时，保留完整源素材。**包中制作项目的选用输出及 take 素材始终完整保留**，不按其标注裁剪。视频输出 MP4（首视频轨及首音轨），音频输出 WAV（首音轨）；这不是所有轨道的无损归档。

标注时间、逐词时间、关键帧时间和故事节点时间同步减去裁剪起点；编码器若把奇数宽高补齐为偶数，将按新尺寸重新归一化矩形、多边形、关键点和关键帧矩形。媒体与标注 `sourceAnchor` 保存原始 ID、原始区间以及媒体摘要；原始 ID 属于外部来源标识，不是包内引用。再次裁剪时记录直接输入素材的来源，不保证保留更早的完整变换链。裁剪不修改原片和原项目。

媒体处理以音画共同时间起点解释区间，保留各流相对时间；延迟音轨在波形／音频导出中补齐起始空白。当前锚点仍按秒保存，编码器实际时长／帧边界可能有量化误差，尚不提供任意容器、多音轨或 VFR 的逐源帧精确映射。

## 明文交换与训练数据集

`desktop/portable.mjs` 输出的是**明文**数据集，同时保存 `manifest.json` 完整元数据和媒体，不能把它当成加密 `.cbox`。支持：

- JSONL：每行一个标注与其媒体记录，JSON 编码保留换行及引号，源路径替换为包内相对路径。
- SRT：每媒体一份字幕及 `subtitles.json` 索引，以说明或标签作为字幕；转义尖括号与控制字符，不把任意标注文本解释成字幕代码。重叠标注允许重叠字幕。
- COCO：要求选中标注全部为带矩形或多边形的视觉标注；否则整次导出拒绝。视频在每条标注起点抽取真实 PNG，图片转为 PNG，归一化几何换算到实际像素；COCO 表达的是起点样本，不表示完整时间轨迹，完整关键帧与原始说明仍在旁边的清单中。

所有格式都采用新目录、受控 staging 和失败清理，不覆盖已有目标。

`desktop/dataset-preparation.mjs` 另提供训练准备流程：按审核、置信度、观察性质等条件检查现有元数据，按来源／剧集／实体生成可复现的 train／validation／test 分组，导出媒体、`samples.jsonl`、分组 JSONL、报告、数据集卡和完整清单。它不训练模型，也不把元数据检查当成文件完整性验证；实际导出才核对文件摘要。

训练行包含原始 `originalAnnotation` 与导出后 `annotation`，保留来源坐标和相对媒体路径；裁剪后的时间、逐词、关键帧属于输出片段时间轴。训练快照不包含制作项目／takes。已知且无歧义的重复裁剪来源可组合，有歧义则保留最近明确锚点并报告；普通 `.cbox` 裁剪仍只记录直接输入来源，不能互相推导更强的谱系保证。

所有切分模式都合并已知同源内容与裁剪祖先，剧集和实体模式再增加相应连接；比例不是固定配额，未知重复与身份无法自动合并。详见[数据集准备](DATASET_PREPARATION.md)。制作资料包同样是独立明文交接格式，含设定集／镜头／参考／总览图与候选输出，不是训练格式或任何厂商 API 请求，见 [AIGC 工作流](AIGC_WORKFLOW.md)。

细粒度字段 `words`（逐词起止时间、文本、置信度）与 `keypoints`（索引、归一化 x/y、模型 z、visibility）通过加密包及 JSONL/完整清单保留。裁剪同步平移逐词时间；补边时重新归一化关键点 x/y，模型给出的有符号 z 原样保留，它不是公制深度或已重投影的三维坐标。COCO 当前仅导出框/多边形，不声称完成姿态骨架映射；关键点仍保存在旁边的完整清单。
