# CBox 格式实验 0.1 与桌面清单

`.cbox` 是加密的描述与标注清单，旁边的 `media/` 保存对应素材。它不是视频编码格式，不是模型权重，也不是版权/授权证明。此实验不兼容任何现有同扩展名产品，发布稳定格式前需检查命名和格式冲突。

## 两个必须分开的决定

- **描述加密模式（本轮实现）**：`.cbox` 内 JSON 加密；外部素材仍是明文，可以独立播放。清单包含相对路径、字节数、SHA-256、标注，密文认证成功后再校验素材。
- **全包保密模式（后续）**：描述和媒体都加密，分块流式读取；需要明确分块认证、顺序、长度、截断防护、随机读取、密钥分发与恢复。不能把明文媒体文件夹压缩一下就称加密包。

不存在既让任意工具无需密钥直接读取素材、又保证这些素材保密的方案。用户选择加密描述并不自动意味着需要 DRM。

## 实验字节格式

| 区间 | 长度 | 内容 |
| --- | --- | --- |
| 0–7 | 8 | `CBOX 00 01 00 00`，确切字节以实现 MAGIC 为准 |
| 8–23 | 16 | 安全随机 salt |
| 24–35 | 12 | 安全随机 AES-GCM nonce |
| 36–末尾 | 可变 | UTF-8 JSON 的 AES-256-GCM 密文 + 16字节 tag |

KDF 为 scrypt(N=32768,r=8,p=1,length=32)，口令 UTF-8 编码、不做隐式规范化，至少12字符；长度限制不是高强度口令保证。header 全部作为 AAD 认证。每次封装重新随机生成 salt 和 nonce；重复 JSON 会产生不同密文。版本固定 KDF 参数，读取方不执行包自带的任意高成本参数。最大明文8MiB，最多1万素材/10万条标注；正式大库应分卷，不把所有帧 mask 内嵌到 JSON。

仅泄露版本、salt、nonce和密文长度；不在明文 header 放标题或人物信息。无压缩阶段，没有 zip 解包。临时输出0600、完成后不覆盖式原子发布，拒绝已有输出。

## Python 原型 JSON 子集

```json
{
  "schema": "cutbox.prototype/0.1",
  "collection_id": "synthetic-tone-example",
  "assets": [
    {"id": "tone", "path": "tone.wav", "size": 32044, "sha256": "由实际文件计算的64位十六进制摘要"}
  ],
  "annotations": [
    {
      "id": "a1", "asset_id": "tone", "predicate": "sound.description",
      "value": "Synthetic tone, not speech", "review_state": "accepted",
      "selector": {"type": "audio_samples", "start": 0, "end": 16000, "sample_rate": 16000}
    }
  ]
}
```

这是形状示意，摘要占位文字不可通过验证。运行 `scripts/cbox.py demo` 可生成真实 WAV、摘要和可验证 JSON。实验仅支持 asset 和 audio_samples；后者读取 WAV 头验证范围和采样率。未实现完整视频/空间/关系 schema，未审计任意扩展字段，不把通过原型检查解释为全本体合法。

## 导出与回读

Python 原型的 pack 读取已有清单与素材，验证后只写 `.cbox`，不复制、裁剪或打包媒体。传递时需要同时复制素材目录。verify 先认证解密，再验证 schema、ID引用、相对路径、大小、SHA-256和已支持的锚点；成功后只报告计数，不把敏感 JSON 打到终端。

路径只接受相对 POSIX 路径，拒绝 `..`、反斜线、驱动器/冒号、空路径段与符号链接；禁止同路径大小写冲突。包不含可执行命令，导入时不执行链接、脚本或自动网络下载。原型不防御另一个本机进程在校验期间并发替换文件的竞态；正式导出需使用受控 staging、文件句柄与快照验证。

SHA-256绑定内容，不证明作者身份。AEAD证明持有该密钥的数据一致性，不证明密钥持有人是谁。后续有跨组织来源签名需求时另加签名身份和撤销机制；不要从加密推导可信作者。

## 稳定格式前的缺口

完整schema与迁移、双方兼容测试向量、增量大集合、全包流式加密、密钥轮换/系统钥匙串、多接收者密钥封装、视频与多轨时间映射、安全评审尚未实现。丢失口令不能恢复；实验数据保留明文源与备份。正式版本优先评估成熟容器/加密封装能否承担外层，不自行发明密码算法。

## Electron 桌面包（已实现）

`desktop/packages.mjs` 使用相同的字节信封与固定密码学参数，但明文 schema 为 **`cutbox.desktop/0.1`**。它与 Python 的 `cutbox.prototype/0.1` 是两种不同清单，当前没有自动迁移或互相导入支持；不能因信封相同就认为应用层兼容。

桌面清单保存 `media`、`entities`、`annotations`、`collections` 四个数组。媒体记录包含相对 `media/<sha256>.<扩展名>` 路径、字节数和 SHA-256；实体包含类型、名称、说明、标签、关联媒体和封面；标注保存源媒体、可选实体、秒级区间、说明、审核状态和可选归一化矩形；集合保存这些对象的 ID 引用。源文件绝对路径和本机缩略图路径不写入导出清单。实体选择和集合选择会携带所需依赖，导出的集合引用必须完整。

导出在同级临时目录中复制媒体，核对复制结果与库内记录的大小和 SHA-256，源文件被原地修改时拒绝导出，避免把旧标注悄悄绑定到新内容。清单加密完成后，独占保留新的目标目录再以重命名发布内容；已有目录（包括空目录）不会被覆盖。发布前可能短暂看到空的保留目录，失败时清理自己创建的临时文件。

**桌面集合包复制完整源媒体，不会按标注区间裁剪。** 包含一个片段的标注，也会携带它引用的整部源视频；素材体积和共享范围应据此判断。独立参考视频/片段导出是另一条媒体处理流程，不能把集合导出称为已裁剪片段包。外部 `media/` 始终是明文。

导入先验证信封认证、8 MiB 清单上限、计数、ID 引用、区间、相对路径、文件大小与摘要，拒绝路径穿越与符号链接；再复制到新的本地托管目录，并重新校验副本。领域服务通过 SQLite 事务导入快照、重新分配对象 ID、按内容摘要去重媒体并重映射引用；事务失败不写入部分元数据。文件复制与 SQLite 不属于同一个原子事务，调用方负责数据库导入失败时清理新建的托管目录。

上述检查不构成对恶意本机并发进程的隔离，也不证明素材作者身份。完整本体、稳定迁移协议、跨实现兼容向量及独立安全审计仍待完成。
